# Slice S0.5 — 3-Minute Demo Script & DoD Checklist

## 3-Minute Walkthrough

1. **Create a Knowledge Base & Ingest Structural Documents (0:00 – 0:50)**
   - Open `Knowledge & Memory` in the Web Console (`/w/default/e/dev/knowledge`) and click **+ New Knowledge Base**.
   - Create `Operations Runbook KB` (`1536`-dim HNSW vector index strategy per `DOC-Q-008` / [ADR-0009](../adr/0009-pgvector-hnsw-and-dimension-strategy.md)), then submit **Ingest Document** (`POST /api/v1/knowledge-bases/{id}/documents`) with Markdown headings, SLA tables, and code blocks (`N.2.11`).

2. **Incremental Hash-Diff Re-Sync (`N.2.11`, `E0.5-3`) (0:50 – 1:30)**
   - Edit only one policy paragraph in the document update box and click **Re-sync Document** (`POST /api/v1/knowledge-bases/{id}/sync`).
   - Observe the incremental sync report showing only the single modified chunk was re-embedded (`re_embedded_chunks: 1`) while unchanged sections retained their embeddings (`unchanged_chunks >= 1`).

3. **Ask this KB & Clickable Citation Chips (`N.2.10`, `E0.5-4`) (1:30 – 2:10)**
   - Enter a query (`How fast do standard refunds complete?`) and click **Ask KB** (`POST /api/v1/knowledge-bases/{id}/query`).
   - Observe the grounded response containing inline `[cit:<chunk_id>]` markers and click any Citation Chip below to inspect the source document title, section path, character range, hybrid score, and raw passage text. Agents also access this pipeline via the built-in `kb_search` tool (`FR-MEM-3`).

4. **Memory Explorer, Session Rolling Summaries & Right-to-Erasure (`E0.5-1`, `E0.5-2`, `FR-MEM-5`) (2:10 – 3:00)**
   - Switch to the **Memory Explorer** tab, store a scoped memory (`user:user_alice`), search via N.2.10 hybrid retrieval, and compact session turns in **Session Memory & Rolling Summary** while preserving ticket `T-10492` and invoice `INV-9981`.
   - Trigger **Erase Subject Memory** (`POST /api/v1/memory/erase`) to hard-purge all memory items and session summaries for `user_alice` and verify the `memory.erase` audit record (`GET /api/v1/audit-events?action=memory.erase`).
